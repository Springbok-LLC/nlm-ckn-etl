
The NLM-CKN represents knowledge as a directed, typed, experimental evidence based multigraph stored in an ArangoDB database. ArangoDB https://arango.ai/products/arangodb/ is a multi-model database supporting graph, vector, document, key-value, and search with a single query language. Ontologies provide the foundational knowledge graph into which all experimental evidence is subsequently placed. Knowledge is drawn from these ontologies:

[CL](http://purl.obolibrary.org/obo/cl.owl): Cell Ontology
[GO](https://purl.obolibrary.org/obo/go/extensions/go-plus.owl): Gene Ontology
[UBERON](http://purl.obolibrary.org/obo/uberon/uberon-base.owl): Uberon multi-species anatomy ontology
[NCBITaxon](http://purl.obolibrary.org/obo/ncbitaxon/subsets/taxslim.owl): NCBI organismal taxonomy
[MONDO](http://purl.obolibrary.org/obo/mondo/mondo-simple.owl): Mondo Disease Ontology
[HP](http://purl.obolibrary.org/obo/hp.owl): Human Phenotype Ontology
[PATO](http://purl.obolibrary.org/obo/pato.owl): Phenotype And Trait Ontology
[HsapDv](http://purl.obolibrary.org/obo/hsapdv.owl): Human Developmental Stages
[PRO](http://purl.obolibrary.org/obo/pr.owl): PRotein Ontology

Ontologies are downloaded from the OBO Foundry https://obofoundry.org/ in OWL format during database creation to ensure use of the most recent versions. OWL (the W3C Web Ontology Language https://www.w3.org/OWL/) is a semantic web, logic-based language designed to represent knowledge about a domain of inquiry which can be used by computer programs. Since the NLM-CKN is human-scoped, only protein classes explicititly asserted to be in the permitted taxon are retained from the Protein Ontology, and all anatomy classes whose taxon constraints (never_in_taxon, only_in_taxon, and in_taxon, resolved against the NCBITaxon hierarchy) do not rule out the permitted taxon are retained from the UBERON ontology.

Each OWL file is loaded into an Apache Jena (Java) Ontology API  model. Apache Jena https://jena.apache.org/ is a free and open source Java framework for building Semantic Web and Linked Data applications, and the Ontology API https://jena.apache.org/documentation/ontology/ provides a consistent programming interface for ontology application development. The model is used to identify classes in an ontology's root namespace, and statements about those classes whose predicates are drawn from a small set of namespaces (RDFS, OBO, Dublin Core, oboInOwl). Since ontology relations of interest are not asserted directly, but instead are expressed as rdfs:subClassOf a blank, or anonymous, node class expression carrying owl:onProperty P and owl:someValuesFrom Y, P and Y are recovered from the class expression and used to synthesize a single named triple subject-P-Y. This process ensures each ontology contributes its own terms, and the source ontology of each relation is known in the foundational knowledge graph.

NS-Forest results, and data obtained corresponding to each identified gene, provide the expermental evidence to place in the foundational knowledge graph. Data corresponding to each gene is obtained from the Open Targets Platform, NCBI Gene, and UniProt. The Open Targets Platform https://platform-docs.opentargets.org/ integrates publicly available datasets to build and score target-disease associations while annotating targets, diseases/phenotypes, and drugs. Data is obtained from the Open Targets Platform using its GraphQL API https://platform.opentargets.org/api. NCBI Gene https://www.ncbi.nlm.nih.gov/gene/ integrates information to provide nomenclature, Reference Sequences (RefSeqs), maps, pathways, variations, phenotypes, and links to genome-, phenotype-, and locus-specific resources. Data is obtained from NCBI Gene using the Entrez Programming Utilities (E-utilities) https://www.ncbi.nlm.nih.gov/books/NBK25497/. UniProt https://www.uniprot.org/ provides protein sequence and functional information. Data is obtained from UniProt using its REST API https://www.uniprot.org/help/programmatic_access.

In order to express assertions based on this experimental evidence, NLM-CKN uses LinkML to define slots, entity classes, and association classes in a schema. LinkML https://linkml.io/ is an open framework, and ecosystem of tools, to simplify authoring, validating, and sharing data. The LinkML ecosystem provides a generator which produces Pydantic classes which act as the intermediate representation between every evidence source and the graph. Pydantic https://github.com/pydantic/pydantic is a Python package that performs data validation using Python type hints. Each evidence source record is used to create an entity instance of the correct type (e.g. Gene, Protein, CellSet, AnatomicalStructure, etc.), then all entity instances are used to create association instances (e.g. GeneProducesProtein(subject=gene_entity, predicate="nlm-ckn:produces", object=protein_entity) which are written to an intermediate file format for loading into the founcational knowledge graph yielding an integrated graph: cell sets and their marker combinations attached to ontology terms, and those terms in turn attached to molecular, clinical, and bibliographic evidence

Since the integrated graph retains ontology verticess unreachable from any evidence vertex, a subgraph is induced by identifying all vertices that have a path to a cell set vertex which serves as the foundatiional evidence vertex. A multi-source breadth-first traversal to a bounded depth seeded at all cell-set vertices retains every vertex reached together with all edges as the induced subgraph. Ontology ancestor paths are restored under an explicit per ontology policy:

The full hierarchy for CL
Ancestor walks to root along SUB_CLASS_OF for GO, MONDO, HP, PATO, and HsapDv
Ancestor walks along PART_OF for UBERON, the meaningful anatomical relation

Note that NCBITaxon is limited to homo sapiens only, and the protein→taxon relation is not traversed at all since every protein is annotated with its source organism so this one edge class would pull the entire PR back in to the induced graph.

Code for the creation of the database is in repository nlm-ckn-etl. Creation of the ArangoDB database is release-driven: every build is keyed to an immutable upstream release tag on the nlm-ckn repository. External data is fetched and updated at a frequency consistent with each data source. All processes are implemented using Prefect, an open-source Python orchestration engine, and every artifact carries detailed build and version information.
